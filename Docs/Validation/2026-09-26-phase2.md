## Cause and changes

UE 5.8 `FileHelpers.cpp` duplicates a world when `SaveMap` targets another name and the original map already exists on disk. The active world stays the original; the duplicate has new actor identities. The commandlet previously saved the original manifest after creating the copy and returned success, although that copy could not re-verify.

The commandlet now refuses this unsupported copy before import or copy creation. Initial naming of an unsaved world retains the existing GUID/session-checked rebinding path. If a native copy is subsequently loaded and explicitly saved through the service, failed rebinding names the owning map and explains recovery. No GUID, ownership or rollback requirement was relaxed.

Recovery discovery now renders the already-recorded paths in its diagnostic text. It does not load, delete, claim or repair those objects. No lifecycle/commit changes were made, and the runtime module is unchanged.

## Actual interruption reproduction

Close Unreal Editor and build first, then run from the plugin root:

```powershell
& './Tests/Invoke-InterruptedRecovery.ps1' -RunName 'Interruption-UniqueRunName'
```

The script refuses an existing evidence directory or an already-running editor. It starts its own hidden process, checks the ready checkpoint and process identity, terminates only that process, and starts a fresh diagnostic probe. It preserves the generated files and compares their hashes. The fixture has a 45-second wait after readiness; if external termination does not occur, it cancels normally and fails the fixture rather than hanging indefinitely.

The successful final run is under `Saved/Phase2Acceptance/20260926A-Interrupted-Final`:
