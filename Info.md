# UE 5.8 ISM/HISM and Datasmith notes

Reviewed against Epic's Unreal Engine 5.8 documentation on 2026-09-22. This is a documentation review of the current plugin, not a build or real-import test. **Documentation facts** below come from Epic; **project implications** are inferences from those facts and the current source.

## ISM and HISM: documentation summary

- An Instanced Static Mesh component holds instances of **one Static Mesh asset**. Each instance has a transform, while materials, collision, shadows, and many other properties belong to the component. Per Instance Custom Data can pass floats to a material, but it does not make arbitrary component properties independent per instance. [Epic: Instanced Static Mesh Component](https://dev.epicgames.com/documentation/en-us/unreal-engine/instanced-static-mesh-component-in-unreal-engine)
- Epic says ISMs now support per-instance LOD. HISM adds a static hierarchy that can help culling and LOD for thousands of largely stationary instances. Its benefit depends on the scene and target hardware; Epic recommends testing. For a **Nanite-only** workflow, Epic recommends ISM because Nanite handles culling and LOD. HISM can still make sense when Nanite fallback meshes are part of the target workflow. Both component types can reference Nanite meshes. [Epic: ISM versus HISM](https://dev.epicgames.com/documentation/en-us/unreal-engine/instanced-static-mesh-component-in-unreal-engine)
- Nanite supports ISM and HISM, but enabling it is not merely a performance toggle. The UE 5.8 page lists Opaque and Masked materials as supported; unsupported material types can render with a default material and log a warning. Platform and rendering limitations also apply. Nanite build work can be significant across many imported assets. [Epic: Nanite Virtualized Geometry](https://dev.epicgames.com/documentation/en-us/unreal-engine/nanite-virtualized-geometry-in-unreal-engine)

**Project implication:** The default ISM choice is aligned with Epic for Nanite-only scenes. The README's categorical claim that HISM is *harmful* with Nanite is stronger than the documentation supports. Keep the ISM default, but benchmark HISM for non-Nanite or fallback targets. The current `EnableNaniteOnSelection` changes every selected mesh asset without first checking effective material blend modes or target-platform needs; it should report unsupported cases before bulk changes. [`ConVerseHISMLibrary.cpp`](Source/DatasmithHISM/Private/ConVerseHISMLibrary.cpp)

## Datasmith and IFC: documentation summary

- Datasmith creates a **Datasmith Scene Asset** containing asset references, import settings, and a source hierarchy with transforms relative to parents. Placing it in a level creates a Datasmith Scene Actor and child actors. Geometry actors usually reference imported Static Mesh assets, while non-geometry parent actors can carry meaningful hierarchy and transforms. [Epic: Datasmith Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/datasmith-plugins-overview)
- For IFC, Datasmith creates an actor for each IFC object and retains relationships such as site → building → storey → element. Unreal actor names can gain suffixes or sanitized characters, while source IDs are retained in metadata. IFC property sets become a **flat** key/value list, with group names discarded. [Epic: IFC Files](https://dev.epicgames.com/documentation/en-us/unreal-engine/importing-ifc-files-into-unreal-engine-using-datasmith)
- Datasmith metadata is available on imported actors as Datasmith User Data. Some application-specific technical values, including unique IDs or classes where supplied, can instead appear as Static Mesh **Component Tags**. The exact available fields depend on the source format. [Epic: Using Datasmith Metadata](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-datasmith-metadata-in-unreal-engine), [Epic: Datasmith Import Process](https://dev.epicgames.com/documentation/en-us/unreal-engine/datasmith-import-process-in-unreal-engine)
- Full-scene reimport updates the Datasmith Scene Asset; level actors may need a separate **synchronize** step. That step can add, remove, rename, and reparent actors while retaining recognized overrides such as actor transforms and material assignments. Actors deleted in Unreal are **not respawned by default**; synchronization has a “Re-Spawn Deleted Actors” option. Individual asset reimport updates the asset without synchronizing scene hierarchy. Reimport can overwrite mesh geometry or parent materials edited inside Unreal. [Epic: Datasmith Reimport Workflow](https://dev.epicgames.com/documentation/en-us/unreal-engine/datasmith-reimport-workflow-in-unreal-engine), [Epic: Reimporting Datasmith Content](https://dev.epicgames.com/documentation/en-us/unreal-engine/reimporting-datasmith-content-into-unreal-engine)
- Datasmith converts source units to Unreal centimeters, but Epic calls out difficult cases involving parent non-uniform scale and custom pivots. Imported meshes can also gain generated lightmap UVs, while collision and physics may require separate setup. [Epic: Datasmith Import Process](https://dev.epicgames.com/documentation/en-us/unreal-engine/datasmith-import-process-in-unreal-engine)

## Preparing a native Revit export

For a native Revit model going into this UE 5.8 project, use a **`.udatasmith` file** as the first reproducible test input. `.datasmith` is not the documented file extension. Revit 2024 and newer include an Autodesk-managed exporter under **View > Twinmotion > Export to Datasmith File**; for Revit 2016.3–2023, use Epic's compatible Datasmith Exporter plugin and its **Datasmith > Export 3D View** command. Epic does not guarantee compatibility across every exporter and Unreal version, so validate a small export in UE 5.8 before relying on a larger handoff. [Epic: supported software and compatibility](https://dev.epicgames.com/documentation/en-us/unreal-engine/datasmith-supported-software-and-file-types), [Autodesk: Revit Datasmith commands](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-DocumentPresent/files/GUID-98192ABD-4E6F-4AF5-B909-FF0795B0AA39.htm)

1. Make a dedicated **3D view** for the Unreal handoff and activate it before export. Its visible geometry is the export scope. Set category visibility and any view filters deliberately; check Temporary Hide/Isolate and section boxes. A section box can **cut the mesh geometry** of an object that crosses it. View shading and render quality do not set Datasmith mesh quality. [Epic: controlling Revit export](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-datasmith-with-revit-in-unreal-engine)
2. Confirm linked Revit models resolve and that the needed materials and texture files are available. Datasmith includes linked models it can find, translates common Revit material properties, and does not translate procedural textures. [Epic: linked models and materials](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-datasmith-with-revit-in-unreal-engine)
3. Keep repeated objects as proper family instances with intentional parameter values. Epic states that objects in the **same family with exactly the same parameter values** share a Static Mesh asset in the Datasmith scene. Therefore, first measure how much asset sharing direct Revit export already achieves; do not alter design parameters just to increase the converter's hit rate. [Epic: Revit instancing](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-datasmith-with-revit-in-unreal-engine)
4. Keep the Revit instance/type metadata required for traceability. Check the Datasmith metadata export filter: an empty filter exports all metadata, and a configured filter affects both file export and Direct Link. Revit instance/host IDs may also appear as component tags after import; inspect a real sample before deciding the plugin's identity field. [Epic: Revit metadata and tags](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-datasmith-with-revit-in-unreal-engine)
5. Leave tessellation at its default **level 8** unless a sample shows a size or surface-quality problem. If survey-coordinate alignment matters, compare Project Base Point/Project North against Survey Point/True North before export; do not change a coordinated Revit model merely for this plugin. [Epic: tessellation and base points](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-datasmith-with-revit-in-unreal-engine)
6. Export a small representative view first, including repeated family elements, a material override, and a linked-model element if applicable. Keep the generated **`_Assets` folder beside the `.udatasmith` file** when handing it off. Check Revit's Export Messages and, in UE 5.8, record actor count, distinct mesh count, materials, transforms, hierarchy, metadata, and a reimport result **before** running this plugin. [Epic: file export and sidecar folder](https://dev.epicgames.com/documentation/en-us/unreal-engine/exporting-datasmith-content-from-revit-to-unreal-engine), [Autodesk: Export Messages](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-DocumentPresent/files/GUID-98192ABD-4E6F-4AF5-B909-FF0795B0AA39.htm)

**Format choice:** For this project's native Revit-to-Unreal visualization test, start with the `.udatasmith` file. Use Direct Link when frequent Revit updates are the priority; import IFC separately when an IFC exchange deliverable or IFC-specific path is what the project must support. This is a workflow recommendation, not a claim that the formats produce identical geometry, hierarchy, or metadata. [Epic: supported Revit and IFC workflows](https://dev.epicgames.com/documentation/en-us/unreal-engine/datasmith-supported-software-and-file-types), [Autodesk: file export and Direct Link](https://help.autodesk.com/cloudhelp/2026/ENU/Revit-DocumentPresent/files/GUID-98192ABD-4E6F-4AF5-B909-FF0795B0AA39.htm)

## Pre-import processing without populating the working level

Use **Visual Dataprep** for the supported version of this workflow. A Dataprep Asset reads the `.udatasmith` source into a temporary preview world, executes a reusable recipe, and creates project assets and actors only when the result is committed. Set an output folder and a separate output level, and open an empty staging map before committing so the raw Datasmith hierarchy never has to be placed in a production level. The source `.udatasmith` and its sidecar folder remain unchanged. [Epic: Dataprep overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/dataprep-overview-in-unreal-engine), [Epic: Dataprep import customization](https://dev.epicgames.com/documentation/en-us/unreal-engine/dataprep-import-customization-in-unreal-engine)

This project already enables `DataprepEditor`, `DatasmithImporter`, and `DatasmithContent`. Its plugin exposes four Dataprep operations. For the first fixture, use **Analyze ISM Candidates**, followed by **Create Hierarchical Instanced Static Meshes** with identical settings, then compare Dataprep's before/after statistics and inspect the preview before Commit. Despite its display name, the Create operation defaults to ISM when `bUseHISM` and `bAutoDetectFromNanite` are false. Do not include **Consolidate Similar Static Meshes** in the accepted pipeline until Phase 1 resolves its reference-scope and deletion-safety issues. The current Create operation also remains subject to Phase 2's material, placement, and eligibility gates.

Directly editing the `.udatasmith` XML is technically possible but is not the recommended pipeline. The file describes scene elements and references geometry and textures in its `_Assets` sidecar folder; stable names, references, hashes, transforms, hierarchy, and metadata are part of the import and reimport contract. Sharing a mesh reference between multiple Datasmith actors is also different from creating an Unreal `UInstancedStaticMeshComponent`, so rewriting XML alone does not provide this plugin's intended actor/component reduction. If an external rewrite is eventually required, implement and validate a Datasmith SDK exporter or a controlled Unreal automation tool rather than treating the XML as a hand-edited file. [Epic: Datasmith Export SDK](https://dev.epicgames.com/documentation/en-us/unreal-engine/datasmith-export-sdk-guidelines)

## Additional code findings from the follow-up review

These are present in the current source and need disposable-scene tests to measure their effects:

1. **Effective material overrides are grouped but not applied.** `BuildMaterialSignature` reads `SourceComponent->GetMaterial(Index)`, so override variants are separated. ISM creation calls `SetStaticMesh(CanonicalMesh)` and copies selected properties, but never calls `SetMaterial` from that group's source component. The new ISM therefore uses the canonical mesh asset's default materials, which can differ from the source's effective materials. This can visibly change a converted group. Apply and verify every effective material slot before deleting any source actor. [Epic: shared ISM materials](https://dev.epicgames.com/documentation/en-us/unreal-engine/instanced-static-mesh-component-in-unreal-engine); [`ConVerseHISMUtils.cpp`](Source/DatasmithHISM/Private/ConVerseHISMUtils.cpp).
2. **Successful instance insertion is assumed.** `AddInstance` returns an index, but the code ignores it, increments `SourceActorsConverted`, and queues the source actor for deletion. Confirm the instance count and returned index for each group before source deletion; on a partial failure, retain the source and clean up only the staged instances. [Epic: AddInstance API](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/UInstancedStaticMeshComponent/AddInstance); [`ConVerseHISMUtils.cpp`](Source/DatasmithHISM/Private/ConVerseHISMUtils.cpp).
3. **One eligible mesh is not proof that an actor is disposable.** Eligibility checks the number of suitable Static Mesh components. It does not reject an actor with another behavior-bearing component or user data. Converted actors are then unconditional delete candidates. Define which actor/component payloads may be discarded and which require preservation or a skip. [`ConVerseHISMUtils.cpp`](Source/DatasmithHISM/Private/ConVerseHISMUtils.cpp).
4. **Below-threshold groups can leave empty managed actors.** Managed family actors are created during grouping, before `MinInstanceCount` is checked. Empty managed actors are cleaned up only in the cancellation branch. A successful run with only small groups can still change the level even though no source actor was converted. Defer actor creation until a group is accepted or clean empties on every path. [`ConVerseHISMUtils.cpp`](Source/DatasmithHISM/Private/ConVerseHISMUtils.cpp).
5. **Explode is not a lossless reverse operation.** It creates generic actors using the canonical ISM mesh and selected component properties. It does not reconstruct each original mesh asset, IFC actor identity, metadata, original wrapper hierarchy, or other source components. Even after its spawn-failure safety fix, describe it as expanding instances into editable actors, not restoring the Datasmith import. [`ConVerseHISMLibrary.cpp`](Source/DatasmithHISM/Private/ConVerseHISMLibrary.cpp); [Epic: IFC metadata and identity](https://dev.epicgames.com/documentation/en-us/unreal-engine/importing-ifc-files-into-unreal-engine-using-datasmith).

**Priority adjustment:** Material override preservation, instance-add validation, and actor-payload eligibility belong in Phase 2's conversion correctness gate. Empty managed actors belong in the same fixture tests. These are separate from the longer-term reimport and metadata design work.
